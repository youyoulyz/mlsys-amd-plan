# 实验盒 · Experiment Box

这是 hello-mlsys 的**实验性内容**：每个实验都是围绕一个系统问题的"先预测、再实测、再解释"小故事，挑的都是有**反直觉钩子**的——你的朴素直觉会被实测打脸，这正是建立系统直觉最快的方式。

> 每个实验独立可读，不必按顺序。建议节奏：先读「你会怎么猜」并写下自己的预测 → 跑（或读实测）→ 对答案 → 想清楚「为什么会这样」。
>
> 允许用 AI 协助跑实验，但**预测、观察、解释、结论的边界必须经得起检验**。

## 一个重要提醒：硬件档位

这些实验的**实测数据绝大多数在消费级/小卡上跑的**（AMD RX 7900 XTX、NVIDIA RTX 3080，个别是 2× V100 校准），不是 plan 里 T4 的 Instinct MI300。脚本大多可移植（纯 PyTorch / llama.cpp / vLLM，ROCm 能跑），但"现成的数字"来自这些卡。

- **T2（Radeon / 消费卡）档**：直接可用，数字可直接引用。
- **T4（Instinct MI300）档**：脚本能跑，但需要你自己在云端补一轮实测——那恰恰是第 2 周"校准"要练的事。
- 每个 lab 的「硬件」一节都标了它实际在哪张卡上测的，以及对应 plan 的哪一档。

## 怎么用

1. **配合 plan 的每周节奏**：每周实验跑之前，先按本周「学完能做到」的口径写下预测。
2. **缺硬件也能学**：读 lab 里 `results/` 的实测数字 + 解释，把"你会怎么猜"和"实测会看到"对照，同样能拿到反直觉的认知收益；分析类脚本大多可以在本地数据上离线跑。
3. **补 T4 数据**：在 Instinct 上重跑同一个 lab（`code/` 里就是脚本），把消费级卡的数字和 MI300 的数字摆一起，就是第 2 周"校准参数"的一份真作业。
