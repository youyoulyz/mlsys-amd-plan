面向复合智能体工作流的显存与计算协同调度：前沿进展、研究空白与硬件评测规模验证报告在大型语言模型（LLM）推理系统从孤立、无状态的单轮请求模式向复合智能体系统（Compound AI Systems）演进的过程中，任务形态呈现出以代码审查（Code Review）、自动化软件工程为代表的具有分发（Fan-out）与汇聚（Fan-in）特征的有向无环图（DAG）工作流。针对本地与受限计算节点上运行该类任务的系统优化问题，学术界关注的核心不仅在于任务完成时间（Makespan）的缩减，更在于如何解决并发智能体对有限显存的剧烈争顶以及前缀缓存的生命周期错配。本报告针对该方向的研究现状进行系统性求证与量化验证，深入剖析该问题在学术前沿的解决程度、亟待突破的系统机制空白，以及在系统顶会（如 OSDI、SOSP、EuroSys、ASPLOS、MLSys）标准下兼具说服力与可行性的硬件评测规模。一、 学术现状验证：有向无环图工作流推理是否已被解决文献调研与系统分析证实，该问题并未被完全解决，而是正处于从应用层宏观编排向底层执行引擎物理协同深水区迈进的关键分水岭阶段。过去两年间，针对多智能体工作流的显存与请求调度涌现出多条技术路线，但现有方案普遍聚焦于粗粒度启发式规则、静态拓扑模板或长延迟外部 I/O 填补，尚未在底层通用服务引擎内形成统一的闭环解法。1. 现有代表性工作技术图谱当前学术界与工业界在该交叉方向的代表性成果主要呈现四种分化形态：静态与半静态工作流前缀缓存优化（以 KVFlow、PBKV 为代表）：
KVFlow 在智能体工作流中引入“智能体步长图（Agent Step Graph）”抽象，依据节点在拓扑中距离执行的逻辑步长计算权重，优先保留近期即将执行的智能体前缀，并辅以 CPU-GPU 异步预取机制。然而，KVFlow 强依赖结构相对固定的工作流模板，主要针对静态前缀的复用，无法适配动态代码审查中因分支判断和工具返回差异引发的动态图展开。PBKV 虽进一步尝试通过图神经网络（GraphSAGE）预测未知分支路径，但其预测开销与动态准确率在高波动负载下仍存在显著局限。工具调用停顿期的时空显存解耦（以 TokenCake、Continuum 为代表）：
入选 EuroSys 2027 的 TokenCake 直击智能体在等待外部工具执行时的显存闲置瓶颈，其时间调度器利用工具执行的长延迟窗口（数秒至数十秒）将停顿智能体的 KV 缓存异步卸载至主机内存，并在工具返回前预测性回迁；其空间调度器则通过动态分区保护关键路径上的智能体前缀。Continuum 同样采用生存时间（TTL）机制防止工具调用期间的显存被误驱逐。这类系统的高收益高度建立在“存在外部耗时工具调用”的前置假设上；若面对纯模型密集的 Fan-out/Fan-in DAG（如代码审查中多个子智能体连续进行安全、规范、逻辑推理），外部停顿窗口完全闭合，该类卸载机制将彻底失效。显存状态驱动的联合准入调度（以 TOPAS 为代表）：
发表于 2026 年的 TOPAS 认识到前缀缓存保留与请求并发批处理之间存在此消彼长的空间争夺，将多智能体推理形式化为在线“前缀-状态调度问题（Prefix-State Scheduling）”。TOPAS 基于作业完成时间（JCT）效用函数搜索最优的常驻前缀集合与准入请求集合，在 SGLang 上取得了显著的排队加速。然而，TOPAS 仍将每个智能体的前缀视为不可分割的粗粒度黑盒，未深入到底层物理显存树（Radix Tree）对于细粒度思维链分支的重组与修剪。细粒度生命周期回收与负载特征分析（以 CacheWise、KVTether 为代表）：

核心研究空白与系统级复杂性论证现存工作虽然在不同侧面有所建树，但若将研究场景置于以代码审查为代表的显存紧平衡 DAG 工作流中，现有机制仍暴露出一系列核心瓶颈。这些矛盾正是击破“两槽位简单调度、缺乏系统深度”质疑的关键抓手。1. 瞬态思维链（Ephemeral CoT）对共享前缀树的结构性破坏在代码审查任务中，主智能体将基座上下文（包含系统提示词、代码库规则以及目标文件的 Git Diff，体量通常达 30K 至 60K Tokens）并发分发至负责安全性、代码风格与逻辑正确性的多个子智能体。每个子智能体在生成最终判定前，都会展开数千 Tokens 的长思维链（Chain-of-Thought）或终端排查轨迹。在 SGLang 的 RadixAttention 或 vLLM 的自动前缀缓存结构中，这些生成的中间 Token 作为叶子节点直接追加在公共基座树之后。然而，在 Fan-in 汇聚阶段，主智能体仅需提取各子智能体的精炼缺陷报告，所有子分支庞大的中间思考轨迹在后续执行中永远不会被再次访问。传统 LRU 缓存策略具有时间局部性盲区，会将刚生成的瞬态思维链误判为热数据并死锁在显存中，反而导致宝贵的公共基座前缀或即将用于汇总的主节点上下文被驱逐出显存。若粗暴地按 Session 整体驱逐，又会导致挂接在基座上的下游分支发生连锁前缀断裂（Prefix Shattering）。现有文献中尚未出现一种面向前缀树的原位虚拟折叠机制（In-place Virtual Node Folding）：在保持共享基座不变的前提下，通过对物理块映射表的指针级重组，原子化剥离无用的中间思考块，并将子任务的结构化结论原位挂接回基座，实现汇聚节点对多分支结果的零拷贝接入。2. 算力膨胀与总线滞后下的“计算-传输倒挂”物理规律工业界常采用分层存储架构（GPU HBM $\to$ CPU DRAM $\to$ NVMe SSD）并结合 LRU 换入换出来避免重复 Prefill。然而，最新发表于 2026 年的系统评测（如 Tutti 与 EfficientAgent）揭示了被严重忽视的物理现实：GPU 预填充计算吞吐的增速已远超存储与总线 I/O 带宽的增速，盲目从慢速介质搬运 KV 缓存往往比现场重新计算更慢。以 32B 参数量、采用分组查询注意力（GQA）架构的典型模型为例，在 FP8 精度下处理 32K 长度的代码库上下文，其 KV 缓存物理尺寸约为：$$S_{\text{KV}} = 32{,}000 \times 128\text{ KB} \approx 4\text{ GB}$$若通过实测带宽仅有 $2\text{ GB/s}$ 至 $6.8\text{ GB/s}$ 的 NVMe SSD 或低速总线搬运，单向传输延迟高达 $0.6 \sim 2.0$ 秒。在此期间，GPU 张量核心（Tensor Cores）完全处于空等停顿状态。评测表明，使用 SSD 卸载时，GPU 空转气泡时间可占推理总耗时的 72.3%，导致端到端延迟严重恶化。即便走 PCIe 4.0 总线从主机内存拉取（实测有效带宽约 $25 \sim 30\text{ GB/s}$），搬运 4 GB 仍需 $130 \sim 160\text{ ms}$。与之相对，现代计算卡（如 RTX 4090 或 A100）处理长前缀 FP8 Prefill 的吞吐通常可达 $20{,}000 \sim 35{,}000\text{ Tokens/s}$，全量计算 32K 上下文仅需约 $0.9 \sim 1.5$ 秒。若仅需对增量或变动部分进行计算，其耗时仅在数十毫秒以内。由此可形式化定义“重算 vs. 搬运”的动态决策边界。设前缀规模为 $N_c$ Tokens，每 Token 的 KV 缓存字节数为 $\mu$，当前主机到设备（H2D）有效传输带宽为 $B_{\text{H2D}}$，传输启动固定开销为 $\tau_{\text{load}}$，当前硬件在对应前缀长度下的有效 Prefill 每 Token 耗时为 $t_{\text{pf}}$。仅当搬运延迟严格小于重算延迟时，换入操作才具有正向收益：$$\frac{N_c \cdot \mu}{B_{\text{H2D}}} + \tau_{\text{load}} < N_c \cdot t_{\text{pf}}$$现有分层缓存系统普遍缺乏在 DAG 调度层面对该倒挂效应的动态建模与运行时仲裁，这一理论与系统机制的缺失构成了极具价值的研究突破口。3. Scheduling）”的质疑，其根源在于假定了“调度决策与底层显存物理状态相互解耦”。若仅在应用层做单纯的优先级排序，确实仅属于调度启发式策略；但真实的多智能体推理服务系统中，调度决策直接驱动底层前缀树的分支演进，而物理显存块（Block）的分配状态又反向决定了后续任务的执行边界。在显存预算受限时，选择调度哪一个子分支上卡，将直接决定：第一，共享基座在物理显存中的寿命能否延长至其余兄弟分支就绪；第二，释放当前分支所退还的显存块是否足以容纳下游汇聚节点，抑或会产生严重的物理内存外碎片；第三，正在执行自回归解码（Decode）的低计算强度任务，能否与下一个拓扑节点的粗粒度分块预填充（Chunked-Prefill）实现计算核心与显存带宽的互补重叠。将 DAG 拓扑推进速度与底层 Radix 物理块分配表联合建模，其问题本质是“有约束计算图遍历与动态树形显存分配的跨层联合优化”，具有充分的系统设计深度与学术硬度。三、 硬件评测规模评估与叙事重构针对“端侧双卡是否为伪设定”以及“实验评测规模是否偏小”的问题，必须对论文的故事线进行升维重构，并确立符合顶会严苛要求的硬件评测矩阵。1. 拓扑感知的基座锚定与汇聚预留（Topology-Aware Radix Pinning）打破传统 LRU/LFU 算法对“访问时间”的盲目依赖。在基座上下文（如包含完整项目 Diff 与工程规范的前缀）创建时，系统根据 DAG 的拓扑先验为其注入出度计数器与生命周期锚点：基座锚定（Anchor Pinning）：在所有 Fan-out 并行子分支（安全性、规范性、逻辑性审查）未全部执行完成前，将基座物理块强制锁定为不可驱逐状态，阻断底层内存池的随机换页与释放。汇聚反向预留（Fan-in Anti-Starvation Reservation）：监控各子分支的生成进度，当倒数第二个子任务接近生成尾声时，提前在物理内存池中预留汇聚节点所需的上下文槽位，防止新进入的无关外部会话在间隙期抢占显存，消除汇聚启动时的冷启动颠簸。2. 即时思维链原位修剪与虚拟折叠（In-Place Ephemeral Pruning & Virtual Folding）针对子智能体在代码审查过程中生成的超长思维链与中间日志，构建物理映射层面的原子折叠机制：在物理块表（Block Table）中引入“瞬态标记（Ephemeral State）”属性。子智能体输出最终精炼结论时，系统无需进行跨内存物理拷贝，而是通过原子更新 Radix Tree 的节点指针，使结论 Block 直接跨越中间思维链、与共享基座物理相连。同时，将记录中间试错过程的物理 Block 批量解引用并退回物理空闲列表（Free List），实现“零数据搬迁”下的显存即时释放，确保汇聚节点在接纳各分支输出时，显存增量仅受限于结论段本身的体积。3. 基于动态物理代价模型的“传输-重算”准入网关（Cost-Model-Driven Admission Gate）将前述物理代价公式集成至调度循环的准入栅栏中。系统实时采样 PCIe/存储总线的有效吞吐量与当前硬件的 Prefill 计算吞吐：当缺失前缀的数据恢复代价低于原地重算时，调度器启动异步主机内存拉取流水线，并允许当前任务进入就绪队列。若系统检测到总线拥堵（例如多卡并发或主机内存带宽竞争）导致传输时间超过 GPU 原地 Prefill 耗时，调度器强制触发“原位分块重算（Chunked Re-prefill）”，拒绝发出 I/O 搬运指令，彻底规避传输导致 GPU 计算核心长时间饥饿的问题。4. 跨任务非对称分块流水线（Asymmetric Speculative Chunked-Prefill）针对解码阶段计算核心利用率低与预填充阶段显存带宽争用激烈的物理特性，设计跨任务流水线：当某一活动任务处于自回归解码（Decode）阶段时，GPU 处于强内存带宽受限（Memory-bound）状态，张量计算单元具有充裕的闲置算力。调度器利用该空闲计算间隙，按固定预算（如 512 Tokens/Chunk）将队列中下一个 DAG 节点的共享代码上下文切片送入计算管线，提前完成前缀的计算并注入显存。当正在解码的任务吐出终止符时，后续拓扑节点的 KV 缓存已在物理显存中预热完毕，使任务切换时的冷启动时延降至理论极限。五、 结论与推进建议综合前沿文献调研、物理定量验证与顶会审稿规律分析，本报告得出以下结论与推进建议：学术创新空间明确且坚固：尽管 2025 至 2026 年间出现了 KVFlow、TokenCake、TOPAS 和 CacheWise 等代表性工作，但在“处理具备长思维链的代码审查 DAG 拓扑”、“应对预填充算力与总线带宽倒挂的动态代价决策”以及“Radix 树物理块原位虚拟折叠”的系统交集上，学术界仍存在明确的机制空白。该方向具备冲击 OSDI、EuroSys、ASPLOS、MLSys 等系统顶会的充分创新空间。彻底重构论文叙事视角：坚决摒弃“本地个人双卡受限”的应用层调优叙事，将其拔高为“高饱和多智能体工作流下、面向 DAG 拓扑依赖的新型 Serving 运行时架构”。将显存受限定义为任何硬件节点在高并发复合智能体冲击下的“工作集极限饱和态”，从根本上化解关于硬件特殊性的质疑。确立具备充分说服力的硬件评测方案：顶会 EuroSys 2027（TokenCake）与近期顶会预印本（TOPAS、CacheWise）的先例充分证实，以 单卡（A100 或 RTX 4090）作为机制极限压测基准，辅以双卡（Tensor Parallelism = 2）验证多卡环境下的通用性，在学术界完全被认可并具备强大的证据效力。在此基础上，可利用少量云算力租用补充 4 卡或 8 卡的大模型弱扩展性实验，使整套评测证据链严丝合缝。技术落地路线规划：建议避免从零编写推理引擎，直接基于 SGLang（其天然内置的 Radix Tree 数据结构最适于进行树指针原位折叠与分支重组） 或 vLLM（生态覆盖面广） 进行改造。将研究重点集中在显存块生命周期管理器与拓扑感知调度模块的代码实现上，以可控的工程量换取具备坚实系统机制支撑的高质量科研成果。
